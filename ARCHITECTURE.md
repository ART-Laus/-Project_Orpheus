# Architecture — Project Orpheus

## Философия

1. **Один файл — одна песня.** Дубликаты файлов недопустимы. Плейлисты ссылаются на треки, а не копируют их.
2. **Альбомная версия — каноническая.** Если есть версия в альбоме, она главная. Синглы/сборники/переиздания — только если трек не выходил в альбоме или есть ручное решение (концерты, демо, любимые ремиксы).
3. **Библиотека важнее плеера.** Структура файлов не зависит от приложения. Смена плеера не требует перестройки.
4. **Никакой зависимости от Spotify.** Spotify — только источник списков музыки.

## Будущая медиатека (не создаётся на этапе 1)

```
Library/
    Исполнитель/
        Альбом/
            Треки.aac
```

Плейлисты живут вне файловой структуры (логическая сущность).
Обложки — только внутри аудиофайлов (никаких cover.jpg / folder.jpg).

## Внутренняя база (data/db)

Пять JSON-файлов, ключи — Spotify ID:

| Файл | Содержимое |
|---|---|
| `spotify.json` | версия, даты, прогресс импорта, счётчики |
| `artists.json` | исполнители + жанры |
| `albums.json` | альбомы: тип (album/single/compilation), дата релиза, обложки, список треков |
| `playlists.json` | плейлисты: **только ссылки на Spotify ID треков** |
| `tracks.json` | треки: полные метаданные + статусы + источник (лайк/плейлисты) |

Все операции идемпотентны: повторный импорт доливает данные, не дублируя.

## Статусы треков

Каждый трек несёт набор флагов (одновременно несколько):

```
downloaded             файл в медиатеке
metadata_verified      теги соответствуют канону
cover_verified         встроенная обложка >= 1000x1000
canonical_version      хранится альбомная версия
manual_review          требует ручного решения (по умолчанию)
replaced_with_original заменён на оригинал вручную (для русскоязычной музыки)
```

Плюс поле `notes` для ручных пометок.

## Импортёр

- OAuth (scopes: `user-library-read`, `playlist-read-private`), токен в `.cache`
- Лайкнутые треки и все плейлисты, по 50 за запрос
- Обработка rate limit (429 с Retry-After, 5xx — ретраи с паузой)
- Инкрементальное сохранение: при прерывании запуск продолжает с места остановки
- Сырые ответы API — в `data/raw/` для аудита
- Плейлистные треки, не попавшие в лайки, тоже попадают в базу (флаг `liked: false`)

## Контроль качества (этап 3)

`orpheus stats` уже даёт входные данные: покрытие ISRC, дубли по ISRC,
кандидаты-дубли по имени+исполнителю, типы альбомов, битые ссылки плейлистов.

## Долгосрочная архитектура

```
Медиатека (Library/) → ПК-резерв → домашний сервер → Navidrome/Jellyfin
→ Symfonium на телефоне → прослушивание через личный VPN
```

Структура библиотеки не меняется ни на одном этапе.
